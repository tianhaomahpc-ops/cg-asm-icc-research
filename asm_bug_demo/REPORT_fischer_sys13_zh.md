## 0. 结论

- **Sys3:成立,而且是三个系统里收益最大的。** 现行 `-fischer3` 在 regime 0 是 **±0%**(实际比冷启动多 19 次迭代),修好窗口 **−76.3%**;regime 2 是 −69.2% → **−98.2%**。
  **⇒「Sys3 初值类封顶 ~10%」是坏淘汰规则的产物,不是物理上限。**
- **Sys1:也成立**(−10.9% → −62.8% / −67.9% → −98.6%),但 Sys1 只占三系统总迭代的 **~5%**,而且 **warm 单独就有 −27.8%(免费)**。而且现在的停机判据用的是 `rtol`,**不改的话任何初值都省不了迭代**。

## 3. Sys3:「封顶 ~10%」的结论要推翻

`RESEARCH_Sys3_acceleration_zh.md` §3.1 的结论是"初值类封顶 ~10%"(warm −9%、Fischer −11%),理由是"残差留在那 ~8 个慢的交界变化模里"。测试台上:

- 现行实现确实**接近 0**(regime 0 是 +0.03%,regime 2 是 −69.2% —— 后者只是因为相对阈值把基冻结在 4 个向量、根本没触发淘汰);
- **同一份数据、同一个窗口大小,把窗口改成"最近 m 个解"就是 −76.3% / −98.2%**。

**为什么 Sys3 反而是三个里最好的?** 因为躯干解是界面数据的**调和延拓**——体导体是个低通滤波器,前沿的细结构在体内被抹平。解轨迹的数值秩(88 个采样快照的 Gram 特征值):

| 相对阈值 | 1e-4 | 1e-6 | 1e-8 |
|---|---|---|---|
| Sys2 解 `u_e`(regime 0) | 10 | 18 | 34 |
| **Sys3 解 `u_T`(regime 0)** | **3** | **6** | **9** |

心脏里 34 维的东西,到躯干只剩 9 维 —— 一个 16 维窗口绰绰有余。

> 与 `-leadvol` 的"80 步张 ~54 维"不矛盾也不能互相替代:那是**真躯干几何 + 全场 13–16% 精度**的降基实验,这里是立方体模型问题,秩肯定被低估。但机理(调和延拓 = 低通)是真的,**值得在真机上直接量一次 Sys3 解快照的谱** —— 这个数就能直接回答"54 维到底是不是初值的障碍"。

## 4. Sys1:能做,但先修停机判据

`forward_ecg.cpp` 现在:`cg1.iterative_mode = false`(:688,连 warm 都没开)、`cg1.SetRelTol(1e-10)`。

**问题**:PETSc 默认判据是 `‖r_k‖ ≤ rtol·‖r_0‖`,`r_0` 依赖初值。初值越好 `r_0` 越小,**要下降的位数一点没变** ⇒ 在 rtol 判据下任何初值都省不了迭代。你们 Sys2 的代码正是用 `SetRelTol(0.0); SetAbsTol(1e-8*bn)`(:2547-2548)绕开的,Sys1 还没做。

改法(顺序不能反):

1. `cg1.SetRelTol(0); cg1.SetAbsTol(1e-10*‖b‖)` + `KSP_NORM_UNPRECONDITIONED` + `KSPSetInitialGuessNonzero`。
   **保持 1e-10**,别顺手改成 1e-8——那等于白送几次迭代,会污染对比。
2. 只开 warm(零存储、零 matvec):测试台上 **−27.8%**。
3. 窗口回收:测试台上 −62.8%(regime 0)/ −98.6%(regime 2)。

**但先算账**:Sys1 占三系统总迭代的 5616/118437 ≈ **5%**;维护一个窗口 ≈ 1 matvec + 2 归约 ≈ 1 次迭代 ≈ 16 次里的 6%。**结论:warm 免费拿 −28% 就够了,窗口回收对 Sys1 是最低优先级。**

## 5. 每个系统该配多大的窗口(m 扫描)

**先说结构**:三套窗口在代码里**本来就是分开的**,而且必须分开 —— `fisch_P`(Sys2,心脏 `nloc`)和 `f3_P`(Sys3,躯干 `Xt.Size()`)在不同网格上、长度不同、算子不同;Sys1 现在没有窗口。所以问题不是"要不要各自一套",而是**各自该配多大**。

扫 m ∈ {4,8,12,16,24,32,48,64}(同一个真滑窗,只改 m),同时用一个 flop 模型扣掉**维护窗口本身**的开销:

```
一次 CG 迭代  ≈ 1 matvec + 1 PC + 2 点积 + 3 axpy   ≈ 24 N
一步窗口维护  ≈ 2m 点积 + m axpy + 1 matvec         ≈ (6m+13) N
⇒ 窗口开销 ≈ (6m+13)/24 ≈ 0.25 m + 0.54 次迭代/步
```
(点积批成 O(1) 次归约,所以这个比值是**每个 rank 的本地 flop**,在任何规模上都成立。)

**regime 0(轨迹高秩)** —— 上行 = 实测降幅,下行 = 扣掉窗口开销后:

### 决定窗口大小的是两件事

1. **轨迹的有效维数** —— 窗口盖得住才有额外收益。Sys3 的轨迹是 9 维,所以 m 从 4 涨到 8–16 有明显提升(70.3 → 76.3);Sys2/Sys1 的轨迹是 34/29 维,**任何可行的窗口都盖不住**,于是窗口退化成一个"时间外插器",**4 个最近的解就够了**,再多纯属白拿开销。
2. **每步的迭代数** —— 决定开销占比。Sys1 每步只有 16 次迭代,m=16 的窗口就吃掉 4.5 次(28%),m=64 时维护比求解还贵(降幅变负)。Sys2/Sys3 每步 ~160 次,m=12 只占 2%,所以吃得起。

### 推荐值 vs 现在的代码

| | 现在 | 实测最优(扣开销) | 结论 |
|---|---|---|---|
| **Sys1** | 没有窗口 | **m = 4** | 加一个 4 向量的小窗口(比只用 warm 的 −27.8% 好很多);再大就亏 |
| **Sys2** | `FISCH_MAX = 16` | **m = 4–12** | 略偏大,但只值 1–2 个百分点,不急着改 |
| **Sys3** | `F3MAX = 12` | **m = 8–12** | **正好** |

**所以窗口大小本身并没有配错**(Sys3 的 12 是最优、Sys2 的 16 只大了一点点)——**错的是淘汰规则**(§3)。补丁修的正是后者;m 保持原值即可。

> 这一节取代了本报告早先"m=16 vs 64"的粗比较:那一版只测了两个点,得出的"大窗口更差是因为系数抵消(254–1300 倍)"仍然成立,但完整扫描给出了更有用的结论 —— **最优 m 很小,而且按系统不同**。

## 6d. 窗口之后还剩多少?(`fig_deflate_compare.png`)

在修好的滑窗之上再加**两层加性粗空间**(`z = D⁻¹r + Z E⁺ Zᵀr`,与 `TwoLevelNicolaides` 同构),
两种候选粗空间:**几何**(64 个子域示性函数,局部支撑 ⇒ apply 是 O(N))vs **快照**(窗口里的解,
全局稠密 ⇒ apply 是 O(kN) 每迭代)。粗空间的 apply 成本全部计入时间。

**regime 0(保守工况)**

| | 不做回收 | 修好的滑窗 | **滑窗+几何粗空间** | 滑窗+快照当粗空间 |
|---|---|---|---|---|
| Sys1 | 5616 / 15.4 s* | 2048 / 0.74 s | 2093 / 0.81 s | 2100 / 0.96 s |
| Sys2 | 57214 / 15.74 s | 24980 / 7.03 s | **10523 / 3.41 s** | 23059 / 8.80 s |
| Sys3 | 55607 / 15.73 s | 13708 / 4.15 s | **5285 / 1.99 s** | 11604 / 5.79 s |
| **合计** | 118437 / **33.0 s** | 40736 / **11.9 s**(2.77×) | **17901 / 6.21 s(5.31×)** | 36763 / 15.6 s |

<sub>* Sys1 cold 是 1.54 s(表格排版)。</sub>

**regime 2**:合计 113064 / 32.0 s → 滑窗 5797 / 2.31 s → 滑窗+几何 4263 / 2.04 s
(窗口已经吃掉绝大部分,粗空间的边际收益很小)。

### 三条结论

1. **粗空间和窗口正交,叠加后再拿一倍**:Sys2 迭代 −56.3% → **−81.6%**、时间 −55.3% → **−78.3%**;
   Sys3 迭代 −75.3% → **−90.5%**、时间 −73.6% → **−87.3%**。合计从 2.77× 到 **5.31×**。
   分工很清楚:**窗口把容易的步变成 0 迭代,粗空间把剩下的难步变便宜。**
2. **把回收快照当粗空间几乎没用**:Sys2 −56.3% → −59.7%(只多 3.4 个点),而**时间反而从 −55.3% 恶化到 −44.1%**。
   两个原因:(a) 那个子空间已经被当**初值**用过一遍,再 deflate 是重复劳动;(b) 快照是全局稠密向量,
   apply 是 O(kN),每迭代成本涨 60–130%。
   > 这给"回收快照当 deflation → 76→15(−77%)"补上了适用条件:那个结论是在**没有同时把快照当初值**时成立的。
   > 一旦窗口已经在做初值,再把同一批向量当粗空间是重复的 —— 该配的是**几何/代数**粗空间(Nicolaides/GenEO)。
3. **Sys1 不该配粗空间**:单独用是 −3.6% 迭代 / **+7.3% 时间**(regime 2 里甚至 +7.9% 迭代)。
   cond 1.4、0 个慢模,没有慢模可治 —— 和你们 `DESIGN_3000core_zh.md` 里"Sys1 不加粗空间/回收"的判断一致
   (回收还是要的,粗空间不要)。

### 成本说明

- 几何粗空间 setup = 64 次 matvec,**一次性** 0.04 s,被 350 步摊销(真机上被 10³–10⁴ 步摊销,更不值一提)。
- 几何 apply = 一次分段求和 + 一次 k×k 回代 + 一次散射 ≈ 2N + k²,**约一次 CG 迭代的 10%**。
  (第一版把 E 的特征分解放进了 apply,导致 +3000% 的时间 —— 真实现是一次分解、每迭代只回代。)
- **真机提醒**:3000 核上粗解本身是个 collective,你们 `DESIGN_3000core_zh.md` §4 算过分档
  (m=3000 只有稀疏 Chol 22–43 µs 可行)。所以**时间上的加速会小于这里的 5.31×**,迭代上的 6.6× 才是可搬的部分。
